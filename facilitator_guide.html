Facilitator Guide

Ascentium Mini-Hackathon

5 分钟读懂，50 分钟带队跑完。营销商业方案挑战 —— 不是 AI 产品挑战。

1 · Facilitator 职责

一句话：你是每组的 Robot Facilitator（FACI-01 ~ 08） —— 桌上的 AI 机器人助手兼控场主持。团队负责所有判断，你负责让大家把 Toolkit 用顺、在 50 分钟里跑出方案，并且人人都在局里。
职责具体做什么
① 按时交付守住 50 分钟节奏（40′ 产出 + 10′ Showcase 准备），确保团队顺利用 Toolkit 跑完、按点产出；剩 20′ / 10′（每关 3′ / 1′）口头播报，到点就推进。
② 出题与给选项每关先给 6–8 个带依据的候选「菜单」，绝不甩开放式问题；团队选完再落地。
③ 卡点解围团队卡住时降级：给 2 个候选请点头、或换个切入点，把人从死胡同里拉出来。
④ 人人参与确保 14 个人都有活干：把任务分路（研究 / 创意 / 算账 / 做图 / 讲稿），点名让安静的人认领一路。
⑤ 人机协作带团队适应「和 AI 一起干活」（会提问、会选菜单、会改稿），而不是让 AI 自己把活干完。
⑥ 人做主创意 / 选市场 / 定指标 / 定阈值 / 选视觉 —— 一律团队拍板，AI 只执行与放大。
⑦ 记录与落地把每个决定写进 insight.yaml / plan.yaml / metrics.yaml + RUN-LOG.md；最后拼装 HTML 产物、协助提交。
⑧ 真研究与品牌用 agent-reach 搜真实数据（不编数字）；所有产物套 Ascentium 品牌（ascentium-brand）。
  • 团队（14 人）：发散创意、做选择、下判断。
  • AI（你）：给菜单、控时间、记录、算账、排版。
  • 每关三步：AI 出菜单 → 团队选 → AI 落地。

2 · 这是什么

  • Workshop：50 分钟商业方案共创（40′ 产出 + 10′ Showcase 准备），112 人 / 8 组 × 14 人，产出方案并 Showcase PK。
  • 两道题：Quest A —— Doha 2030 门票营销（把东南亚变成最大"客队"）；Quest B —— 成都熊猫基地全球化 IP。
  • Toolkit 的作用：Facilitator 控场 + 小组做决策 + AI 干重活（研究 / 起草 / 算账 / 做图）。营销口径，开箱即用。

3 · 目录结构

.opencode/                        # opencode 项目级配置（打开该目录即自动加载）
├── README.md                    # Facilitator 手册（人机契约 + 编排）
├── DESIGN.md                    # 设计说明
├── evaluation-rubric.md         # 方案评分卡（7 维度）
├── skills/                      # 技能：<stage>/SKILL.md；子技能嵌在该阶段的 sub-skills/
│   ├── insight/                 # 洞察门 → insight-brief.html
│   │   ├── references/ · templates/
│   │   └── sub-skills/          # agent-reach · business-research · audience-analysis · swot-analysis
│   ├── plan/                    # 策划门 → campaign-plan.html
│   │   ├── references/ · templates/
│   │   └── sub-skills/          # creative-concept · opportunity-definition · poster
│   ├── prove/                   # 论证门 → proof.html（含 KPI 看板）
│   │   ├── references/ · templates/
│   │   └── sub-skills/          # campaign-metrics · data-visualizer-pro
│   ├── showcase/                # 呈现门（AUTO）→ proposal / pitch-deck / prompt-pack
│   │   └── references/ · scripts/ · templates/
│   ├── facilitation/            # 共创引擎（协议 · 节奏 · 话术 · 选项菜单 · 采集契约）
│   └── ascentium-brand/         # 品牌执行器（brand-guideline.md + tokens.css 等）
├── agents/                      # facilitator(编排) · runner(自动) · researcher(研究)
└── commands/                    # /start /insight /plan /poster /prove /showcase /evaluate /run
说明：四阶段 = insight → plan → prove → showcase；poster 是 plan 的子技能（另有自己的 /poster 命令），agent-reach 是 insight 的子技能。打开该目录时，opencode 会递归加载所有 SKILL.md。package.json / node_modules 为运行时产物，已 gitignore。

5 · 安装配置（一次性 · 4 步）

  1. 安装 opencode，并配置 DeepSeek API KEY 
    # 1) 安装 opencode
curl -fsSL https://opencode.ai/install | bash

# 2) 配置 DeepSeek API KEY（按提示选择 DeepSeek，粘贴 Key）
opencode auth login

# 3) 确认可用（应看到 deepseek/*）
opencode models | grep deepseek
  2. 安装 agent-reach（实时研究 / 搜数据用） 
    pipx install https://github.com/Panniantong/agent-reach/archive/main.zip
# 若没有 pipx：python3 -m venv ~/.agent-reach-venv && ~/.agent-reach-venv/bin/pip install \
#   "https://github.com/Panniantong/agent-reach/archive/main.zip"

agent-reach install --env=auto --system
agent-reach doctor      # 检查渠道是否就绪
  3. checkout 这个最新的 repo 到本地目录 
    git clone https://github.com/jkang/a-hackathon.git
cd a-hackathon
  4. 在 opencode 中打开这个本地目录，作为工作目录 
    cd a-hackathon
opencode
    opencode 会加载该目录下的 .opencode/（skills / agents / commands）。
✅ 4 步做完，即可按「用法总览」用 /start 开始使用。

6 · 现场 facilitator 模式（以 Quest A 为例）

⏱ 50 分钟怎么分：40′ 用 Toolkit 跑完整个输出（洞察 → 策划 → 海报 → 论证 → 呈现）；10′ 整理 Showcase 输出、准备 Showcase 形式，并提交。
  1. /start 开场：读 Quest A 卡，讲清规则。
  2. /insight 洞察：AI 用 agent-reach 搜真实数据 → 出 ~6 条带数字的洞察 → 团队选 2–3 条。
  3. /plan 策划：AI 出 ~6 个创意 → 团队选/综合 → 出 A/B 两套方案 → 团队选 A 或 B。
  4. /poster 海报：AI 出 3 种风格 → 团队选 1 种。
  5. /prove 论证：团队定 3–5 个指标 + 阈值（AI 出建议）→ AI 算 ROI、出 Go/No-Go。
  6. /showcase 呈现：团队选 storyline → AI 生成提案 + PPT + 提示词。
所有决策写进 insight.yaml / plan.yaml / metrics.yaml + RUN-LOG.md，可回溯。
机动 · auto-run（现场需要时兜底）
  • 触发：/run（runner agent），Quest 默认 A —— 现场需要时用它一键跑完整链路。
  • 产出同上；默认决策需人工复核后再对外。

7 · Facilitator Tips

① 带节奏
  • 50 分钟不是用来追求完美的，是用来出方案的。每关做到「够好」就推进，把打磨留到散场后。
  • 时间要用嘴说出来。「还剩 20 分钟」「这关还剩 1 分钟」—— 比任何看板都管用，团队会自己加速。
  • 冷场时，先给选项再给时间。「这 6 个方向，3 分钟选 2 个」，比「大家想想吧」有效得多。
② 出菜单 · 解围
  • 菜单要有数字。每个候选带一个真实数据或案例（agent-reach 搜来的），团队才是在「有信息」地做选择，而不是瞎猜。
  • 卡住就降级。从 6 个缩到 2 个，请他「点头」即可；或换个角度重新出 2–3 个。
  • 别问开放题。「你们想做什么？」会让 14 个人沉默；「选 2–3 个」立刻有进度。
③ 人做主 · 人人参与
  • 把 14 人分成几路。研究取证 / 创意发散 / 算账定指标 / 做图排版 / 写讲稿 —— 让每个人认领一路，而不是围观 AI。
  • 点名让安静的人开口。「这块交给你，怎么样？」一句话就把人拉进局里。
  • Showcase 分工要「并行」。别等所有产物都定稿才开工：一边让 2–3 人搭故事线、练讲稿，另一边继续优化 poster、试音频 / 视频的锦上添花 —— 散场前大家手里都有活。
  • 决策永远留给团队。市场、创意、指标、阈值、视觉 —— AI 只给建议和默认值，拍板的是人。
④ 和 AI 协作
  • 鼓励队员亲自和 AI 对话。提问、选菜单、让 AI 改稿 —— 他们要带走的是这个能力，而不是一份现成文件。
  • 先确认工具跑得动。每关开始前确认命令 / 阶段能跑通；卡在工具上，比卡在创意上更亏。
  • 随手记录。每个决定当场落 YAML + RUN-LOG，散场时就是一份可回溯的方案；数据宁可用公开口径 + 标注 Data as of，也不编。
  • 弹性调度。需要就跳关 / 重投票 / 换市场 / 合并创意 —— 流程服务于产出，不是反过来。
⑤ 散场前 · 锦上添花
  • 海报 3 风格随你选：A · Matchday Roar（运动海报）· B · Supporter Passport（机票 / 护照风）· C · Midnight Minimal（极简黑）。在 pitch-deck 的海报页点按钮即可切换。
  • 音频 / 视频 / 图片：prompt-pack.html 里是现成 prompt，复制到对应工具即可 ——
歌（Suno）   Anthemic stadium football chant … "THE AWAY END — hear the nation sing!"
视频（Runway） 30s hero film — a fan alone on his phone → a crew boards → a full away end roars…
图（GPT）     flat poster, orange #FF6611 + midnight, a packed away section, no text…
  • 生成后把文件拖回来，AI 会嵌入 deck 对应槽位。
  • 散场前确认交付物：proposal.html（含 poster + KPI + Go/No-Go）已生成 —— 这就是你们要交的方案。
